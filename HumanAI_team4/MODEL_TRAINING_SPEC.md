## 0. 개요

서빙 파이프라인이 소비하는 **두 모델 산출물**을 생성한다.

| 모델 | 역할 | 구성 | 학습 데이터 | 산출물 |
|---|---|---|---|---|
| **YOLO 식별기** (Track 1) | "무슨 약?" 식별 | 통합 1개 | 정상 + **합성불량** | `models/yolo/identifier.pt` |
| **PatchCore** (Track 2) | "정상/불량?" 판정 | **약종별 200개** | 약종별 **정상만** | `models/patchcore/{drugId}.ckpt` |

### 0.1 핵심 원리 (왜 이렇게 나누나)
- **Track 1**은 *비정상(결함)의 생김새*를 배운다 → 결함은 약종 무관하게 전이되므로 **통합 단일 모델**.
- **Track 2**는 *정상의 생김새*를 배운다 → 정상은 약마다 완전히 달라 **약종별 모델**.
- 둘의 증강 정책이 **정반대**라는 점이 이 설계의 핵심(§3).

### 0.2 데이터 현황
- AI Hub 4TB, **정상만**, 200종 × ~200장 ≈ 40,000장
- 분포 특징: 원형/타원형/장방형이 대다수, 분할선 ~1/3 보유, 각인 대다수 보유, 2색 정제 희귀

## 1. ⚠️ 선결 과제 — 실제 불량 평가 셋 (최우선)

불량이 0장이면 **모델 검증 자체가 불가능**하다. 합성으로만 평가하면 낙관적 수치만 나온다.

- **제작 방법**: 실제 알약 물리 손상(긁기·깨기·반점 찍기·일부 절단) 또는 라인 폐기품 수집
- **촬영**: 운영과 동일하게 **휴대폰으로 촬영**(도메인 일치)
- **규모**: 결함 유형별 30~50장, 총 수백 장
- **용도**: **val/test 전용**(학습 절대 금지)
- **착수 시점**: 프로젝트 W1부터 즉시

---

## 2. 데이터 파이프라인

### 2.1 ROI 추출 (공통 전처리)
```
원본 → 알약 검출 → crop → 회전정렬(PCA 주축) → 앞/뒷면 정리 → 정규화(조도/WB) → 저장
```
- 출력 해상도: 식별기 640px / PatchCore 256~320px
- 서빙 전처리(`preprocess.py`)와 **동일 로직** 사용(학습-추론 일관성)

### 2.2 데이터 분할
| 세트 | 구성 | 용도 |
|---|---|---|
| Train | 정상 + (식별기는 합성불량) | 학습 |
| Val | 정상 + **실제 불량 일부** | 임계값·하이퍼파라미터 |
| Test | 정상 + **실제 불량(held-out)** | 최종 성능 보고 |

> 약종 누수 방지: 일반화 검증 시 동일 약종이 train/test에 섞이지 않게 분리.

## 3. 데이터 증강 — 트랙별 정반대 (중요)

| 증강 | YOLO 식별기 (Track1) | PatchCore (Track2) |
|---|---|---|
| 회전·플립·스케일·이동 | ✅ 필수 | ✅ (정상 변이) |
| 조명/노출/색지터 | ✅ 적극 | ✅ 약하게 |
| **cutout / random erasing** | ✅ **유익**(결손 모사) | ❌ **금지** |
| 강한 noise / blur / 색시프트 | ✅ 권장(변색·오염 모사) | ❌ **금지** |
| mosaic / mixup | ✅ | — |

- **식별기**: 깨지고 변색된 약도 식별해야 하므로 **결함 모사 증강이 오히려 유익**. 단, 유사 약종 혼동 방지 위해 색지터 강도 보정.
- **PatchCore**: 증강이 "정상의 정의"를 바꾼다. 결함스러운 증강을 넣으면 **민감도가 떨어진다** → 정상 변이(포즈·조명)만 허용.

## 4. Track 1 — YOLO 식별기

### 4.1 과제 정의
- 입력 ROI → **200종 중 약종 분류 (+ 검출 박스)**
- 단일 200-class 검출기로 **localize + identify 동시 수행**
- 대안: 1-class 검출기 + 별도 분류기 (미결정 §7)

### 4.2 학습 데이터
- 정상 40k + **합성불량** 추가 (라벨 = 약종 그대로 유지)
- 합성불량은 "결함 있어도 같은 약"을 가르치는 용도

### 4.3 합성불량 생성 (분포 조건부)
| 결함 | 합성 방법 | 분포 규칙 |
|---|---|---|
| 깨짐·결손 | 마스크 가장자리 erase | **분할선 보유 약 → 분할선 따라** |
| 긁힘 | 곡선 스플라인·명암 | 표면 전역 |
| 오염·반점 | Perlin 마스크 + 텍스처 blend(Poisson) | 모양 마스크 내부 |
| 변색 | 국소 hue/밝기 시프트 | 단색 약 중심 |
| 각인 결함 | 각인 영역 erase/blur/이중화 | 각인 보유(대다수) |
- 합성에 자동으로 정확한 박스가 따라옴 → 수작업 라벨링 불필요

### 4.4 결함 강도 (스펙트럼)
- 약함→강함 전체를 **log-uniform** 샘플링, 면적 ~0.1~10%, 최소 ~10px
- easy/medium/hard 버킷 라벨링 → 버킷별 성능으로 검출 한계 측정
- ❌ 큰 결함만 만들지 말 것(미세 결함 누락 위험)

### 4.5 모델/학습 설정
- 백본/모델: **YOLOv12-s/m** (3060 적합), 입력 640px
- 사전학습 가중치에서 파인튜닝
- 산출물: `models/yolo/identifier.pt` + `CONF_THRESH`(저신뢰 검토 기준) 캘리브레이션

### 4.6 예상 학습 시간 (3060)
- YOLOv12-s: ~6–8분/epoch, 100ep ≈ **10–14시간**
- YOLOv12-m: 더 김(필요 시 GCP)

## 5. Track 2 — PatchCore (Anomalib, 약종별 200개)

### 5.1 과제 정의
- 약종별 **정상 표준**을 모델링 → 추론 시 벗어남(이상)을 점수·위치로 출력
- 약종별 독립 모델 200개. 서빙에서 식별 결과로 라우팅.

### 5.2 학습 데이터
- 약종별 **정상만** ~200장, ROI 추출(crop+정렬+앞뒷면) 후
- 증강: **정상 변이만**(§3)

### 5.3 Anomalib 설정 예시
```yaml
model:
  name: patchcore
  backbone: wide_resnet50_2     # 또는 dinov2 (정확도↑, 무거움)
  layers: [layer2, layer3]
  coreset_sampling_ratio: 0.1   # 뱅크 크기·속도·정확도 노브
dataset:
  image_size: [320, 320]
```

### 5.4 학습 절차 (약종별 반복)
```
for drug_id in 200종:
    정상 ROI 로드 → Anomalib Patchcore fit
    → val(정상+실제불량)에서 임계값 산출(목표 Recall 기준)
    → export: models/patchcore/{drug_id}.ckpt (+ threshold 메타)
```

### 5.5 예상 학습 시간 (3060)
- 약종당 **~1분**(특징추출 + coreset, backprop 없음)
- 200종 순차 **~2–4시간** (병렬 시 단축)
- 진짜 비용은 학습이 아니라 **추론 속도 + 메모리뱅크 용량** → 해상도·`coreset_sampling_ratio`로 조절

### 5.6 대안 모델 (벤치마크 후보)
Anomalib로 동일 조건 비교 가능: **EfficientAD**(실시간·저메모리), **Reverse Distillation**(정확도 상위), **FastFlow**. 합성불량 적극 활용 시 **DRAEM**도 후보.

## 6. 평가

### 6.1 지표
| 단계 | 지표 | 우선순위 |
|---|---|---|
| 식별(YOLO) | Top-1 정확도, 저신뢰율 | 핵심 |
| 판정(PatchCore) | **Recall@FPR1%** | **최우선(QC)** |
| | Image AUROC, Pixel AUROC/PRO | 핵심 |
| 엔드투엔드 | 식별×판정 통합 정확도 | 핵심 |

### 6.2 검증 원칙
- 최종 점수는 **실제 불량 셋(휴대폰 촬영)**으로만 보고
- 합성불량은 학습 전용
- 3-seed 평균±표준편차(불량 셋이 작으므로)
- 속성별(모양·분할선·각인 유무) 성능 분리 보고 → 약점 파악

### 6.3 비교 실험
| 그룹 | 변수 |
|---|---|
| 이상탐지 모델 | PatchCore vs EfficientAD vs RD (Anomalib) |
| 백본 | wide_resnet50 vs dinov2 |
| 입력 해상도 | 256 / 320 / 512 |
| 합성 ablation | 기법별(Perlin/CutPaste/Scratch) on-off |
| 일반화 | leave-types-out(신규 약종) |

## 7. 미결정 사항 (Open Questions)
1. **앞/뒷면**: 면별 PatchCore vs 양면 통합 1모델
2. **약종 수**: 200 개별 vs 모양×색 클러스터 묶음(모델 수 절감)
3. **YOLO 식별 구조**: 단일 200-class 검출기 vs (1-class 검출 + 분류기)
4. **PatchCore 백본**: wide_resnet50 vs dinov2
