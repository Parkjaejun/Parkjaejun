🔄 "모델 교체"는 어디서? → 서버 PC 안, Docker 속 worker 코드에서
물리적 교체가 아니라 코드가 메모리에서 다른 모델을 불러오는 것이다.
YOLO가 "타이레놀" 판별 → worker가 200개 중 '타이레놀 PatchCore' 로드 → 판정
다음 사진이 "게보린"이면 worker가 '게보린 PatchCore'를 갈아끼운다. Firebase에서는 절대 일어나지 않는다.

2데이터 흐름 (End-to-End)

1
카메라 촬영휴대폰
촬영 가이드로 중앙·거리·조명 표준화
2
이미지 업로드 + 요청 생성휴대폰
Storage에 사진 저장 · Firestore에 status: pending 문서 생성
3
새 요청 감지 (실시간 구독)서버
서버가 Firestore를 outbound로 리스닝 → NAT 통과 (포트개방 불필요)
4
이미지 다운로드 + 전처리서버
검출 → crop → 회전정렬 → 앞/뒷면
5
YOLO 식별 → 약종 결정서버
저신뢰면 "검토 대상" 플래그
6
해당 PatchCore 로드 + 불량 판정서버
🔄 모델 교체 지점 · 정상/불량 + 결함 위치(heatmap)
7
결과 업로드서버
결과 이미지 → Storage · Firestore 문서 status: done 업데이트
8
결과 전달Firebase
Firestore 변경 → 휴대폰에 실시간 전파 / FCM 알림
9
결과 자동 표시휴대폰
정상/불량 + 결함 표시 이미지

예상 지연: 업로드~결과까지 보통 2~5초 (처음 보는 약종은 모델 로드로 +α).

3"다른 PC"는 꼭 필요한가?

휴대폰은 모델을 안 돌리므로, 모델을 돌릴 컴퓨터(=서버)는 반드시 하나 필요하다. 단 그 형태는 선택이다.

선택지서버 역할을 맡는 것물리적 내 PC?
(A) 온프레미스내 GTX 3060 PC를 켜두고 서버로 사용필요 (그 PC)
(B) 클라우드GCP GPU 인스턴스가 곧 서버불필요 (클라우드가 대체)
요약: "물리적 다른 PC가 꼭 필요하냐"는 아니오(클라우드로 대체 가능). 하지만 모델을 돌릴 컴퓨터 자체는 반드시 필요하다. 휴대폰 + Firebase만으로는 추론이 불가능하다.
📱 휴대폰은 찍고 보여주기만 · 🔥 Firebase는 사진·결과를 전달하는 우체국 · 🖥️ 3060 PC(또는 클라우드)가 진짜 일하는 서버 · 🐳 Docker는 그 서버 안에서 모델을 담아 돌리는 상자 · 🔄 모델 교체는 Docker 속 worker가 약종에 맞춰 수행.
